디자인 인계 문서

64×32 LED 매트릭스 UI

건물 축소 모형에 내장되는 HUB75 LED 패널의 화면 디자인. 일반 디스플레이와 제약이 크게 달라서, 작업 전 3번 항목을 먼저 읽어야 합니다.

대상 그래픽 디자이너 산출물 64×32px PNG 현재 상태 개발자 임시 디자인으로 동작 확인 완료
01

무엇을 만드는가

화면이 놓이는 맥락

건물을 1:20으로 축소한 스티로폼 모형 안에, 실물 크기의 LED 패널이 내벽에 부착됩니다. 이 패널이 건물 내부를 2×2 구역(zone)으로 나눠 각 구역의 온도와 습도를 실시간으로 보여줍니다.

즉 화면은 건물 평면도이면서 동시에 계기판입니다. 구조가 읽혀야 하고, 숫자도 읽혀야 합니다. 이 둘의 균형이 이번 디자인의 핵심 과제입니다.

패널 실물 크기는 320×160mm, 픽셀 피치 5mm입니다. 화면상 1px이 실제 5mm짜리 LED 알갱이 하나입니다. 5×7px 글자는 실물에서 25×35mm로, 몇 걸음 떨어져서도 읽힙니다. 작아 보여도 물리적으로는 충분히 큽니다.

03

이 화면의 제약

가장 중요한 항목 — 여기서 대부분의 디자인 판단이 갈립니다

3.1 색은 채널당 8단계뿐입니다

일반 화면은 채널당 256단계(1,600만 색)지만, 이 패널의 드라이버는 채널당 3비트 = 8단계만 표현합니다. 총 512색입니다. 아래가 실제로 쓸 수 있는 전부입니다.

중간값이 없습니다. 두 단계 사이의 색은 존재하지 않아 가까운 쪽으로 튕깁니다. 미묘한 색 차이로 정보를 구분하는 설계는 이 화면에서 무너집니다.

그라디언트는 쓸 수 없습니다. 8단계로는 부드러운 전환이 안 나오고 굵은 띠(밴딩)로 갈라집니다. 넓은 면적의 그라디언트, 부드러운 그림자, 반투명 겹침은 모두 피해야 합니다.

3.2 안티앨리어싱이 없습니다

픽셀은 켜지거나 꺼지거나 둘 중 하나입니다. 곡선과 사선은 계단으로 나타납니다. 1px보다 얇은 선, 소수점 좌표, 둥근 모서리 반경 같은 개념이 존재하지 않습니다. 모든 요소를 정수 픽셀 격자 위에서 설계해야 합니다.

3.3 글자는 직접 찍어야 합니다

기성 폰트를 축소해서 쓸 수 없습니다. 트루타입을 11px 이하로 줄여 1비트로 변환하면 획이 사라지거나 서로 붙어 뭉개집니다. 이 크기의 글자는 픽셀을 하나씩 직접 배치한 비트맵이어야 합니다.

개발 과정에서 실측한 숫자 가독성 한계입니다.

크기판정비고
5×7 굵게현재 사용세로획 2px. 획 면적이 넓어 멀리서도 읽힘
5×7 얇게가능획 1px. 또렷하지만 가늘어 보임
3×5하한선숫자가 구분되는 최소 크기
3×4불가6·8·9가 같은 덩어리로 뭉침
3×3불가2·3·5 구분 불가, 8은 사각형 덩어리

굵은 획을 쓰려면 세로획 2px + 간격 1px + 세로획 2px = 폭 최소 5px이 필요합니다. 가로획까지 2px로 하는 완전 볼드는 높이 8px이 필요합니다.

3.4 기하 제약

2×2 구조를 1px 십자선 하나로 나누면 전체 폭이 항상 홀수가 됩니다(구역크기×2 + 3). 패널 폭은 64로 짝수라서 좌우 여백이 1px 어긋나는 것을 피할 수 없습니다. 완벽한 좌우 대칭을 전제로 설계하면 구현 단계에서 반드시 틀어집니다.

04

현재 구현 상태

개발자가 임시로 만든 것 — 대체 대상이지 기준이 아닙니다

실제 패널 픽셀을 1:1로 시뮬레이션한 화면입니다.

요소좌표
전체64 × 32
중앙 구조도29×29 · x 17–45 · y 1–29
구역 1칸13 × 13
십자 구분선x 31 · y 15 · 1px
좌측 여백x 1–16 (16px)
우측 여백x 46–62 (17px)
글자5×7 굵게 · 자간 1px

구역 색은 온도, 여백의 위 숫자는 온도(℃), 아래 숫자는 습도(%)입니다. 각 구역의 값이 가장 가까운 여백에 배치됩니다. 왼쪽 두 구역은 왼쪽 여백에, 오른쪽 두 구역은 오른쪽 여백에 표시됩니다.

이 배치는 기술적으로 가능하다는 것만 검증한 상태입니다. 여백 폭, 구역 크기, 색 배분, 숫자 위치 모두 재설계 대상입니다. 구조를 완전히 다르게 가도 됩니다.
05

디자인 요청 사항

필요한 산출물

5.1 필수 — 기본 화면

4개 구역의 구조와 각 구역의 온도·습도를 한 화면에 담습니다. 표시해야 할 데이터는 구역당 온도 2자리, 습도 2자리입니다.

5.2 필수 — 상태 변형

상태표현해야 할 것
정상기본 화면
경보특정 구역의 이상 상태. 한눈에 어느 구역인지 판별되어야 함
센서 무응답값을 못 읽는 구역. 0과 명확히 구분되어야 함

점멸을 쓸 경우 주기를 명시해 주세요. 정지 화면 두 장(켜짐/꺼짐)으로 전달하면 됩니다.

5.3 판단이 필요한 지점

  • 구조 우선인가, 수치 우선인가. 벽선을 밝게 하면 평면도로 읽히고, 구역 색을 밝게 하면 히트맵으로 읽힙니다. 둘 다 밝으면 서로 뭉개집니다. 명도 위계를 어디에 둘지 정해 주세요.
  • 단위 표기. 현재는 숫자만 있습니다. ℃와 %를 넣으려면 글자 폭이 늘어 다른 요소를 줄여야 합니다.
  • 온도 색 매핑. 몇 도가 어떤 색인지, 범위와 단계를 정해 주세요. 8단계 안에서 실제로 구분되는 색만 써야 합니다.
06

전달 형식

이대로 주시면 바로 코드로 옮길 수 있습니다

  • PNG, 정확히 64×32px, 1:1. 확대본은 참고용으로 따로 주셔도 되지만 원본은 반드시 실제 크기여야 합니다.
  • 안티앨리어싱 끄기. 포토샵은 연필 도구, 피그마는 확대 후 사각형 배치를 권합니다. 가장자리에 반투명 픽셀이 있으면 사용할 수 없습니다.
  • 색은 8단계 값만. 각 채널이 0 · 36 · 73 · 109 · 146 · 182 · 219 · 255 중 하나여야 합니다. 다른 값은 구현 시 반올림되어 의도와 달라집니다.
  • 글자는 사용할 글리프를 모두 포함해 주세요. 숫자 0–9는 필수이고, 문자나 기호를 쓰면 그것도 픽셀 단위로 그려 주셔야 합니다.
  • 상태별로 파일을 나눠 주세요. 레이어가 아니라 완성된 화면 단위로요.
격자에 맞춰 작업할 수 있게 64×32 템플릿 파일이 필요하면 만들어 드립니다. 요청해 주세요.
07

향후 확장

지금 만들 필요는 없지만 알고 계시면 좋은 방향

이 프로젝트의 원래 구상에는 화재 시 대피 안내가 포함되어 있습니다. 화재 구역 점멸, 출구 표시, 현재 위치, 대피 경로 화살표를 같은 64×32 화면에 띄우는 시나리오입니다.

지금 단계의 과제는 아니지만, 기본 화면 구조가 나중에 이 요소들을 수용할 수 있으면 좋습니다. 특히 큰 방향 화살표가 들어갈 공간을 염두에 두시면 재설계를 줄일 수 있습니다.

질문이나 추가 자료 요청은 개발 담당자에게 전달해 주세요. 이 문서의 시뮬레이션 화면은 실제 패널의 픽셀 수와 색 단계를 그대로 반영합니다.
