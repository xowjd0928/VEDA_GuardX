# 바닥 캘리브레이션 — 재캘리브레이션 절차 (VMS ▸ FLOOR MAP)

> 대상: 운영자·개발자. 소요 ~20분(4채널).
> 마지막 갱신 2026-08-22. 이 문서를 만든 계기는 **현장 캘리브레이션이
> 폰 사진으로 만들어져 있어 발밑점이 근사로만 찍히던 것**이다.

---

## 0. 왜 다시 해야 하나 — 판정 기준 한 줄

VMS 는 캘리브레이션 H(호모그래피)를 **그 H 를 만든 이미지의 픽셀 공간**이
라이브 메타데이터 좌표계와 **같을 때만** 실시간 발밑점 변환에 쓴다.

```
쓸 수 있다(usable)  =  H 가 있고  AND  frame_w × frame_h == 2592 × 1520
```

`2592 × 1520` 은 카메라가 ONVIF 메타데이터의 BoundingBox 를 싣는 픽셀 공간이고
(`crowd_page.h: FRAME_W/FRAME_H`), 캘리브레이션 웹 UI 도 같은 값을 요구한다
("메타데이터 해상도와 다르면 그 H 는 VMS 에서 쓸 수 없다").

**지금 상태(2026-08-22 실측)**

| 채널 | H 를 만든 이미지 | 판정 |
|---|---|---|
| CH1 | 1050 × 1400 (세로 사진) | ✗ 근사만 |
| CH2 | 3024 × 4032 (세로 폰 사진) | ✗ 근사만 |
| CH3 · CH4 | 없음 | ✗ 미보정 |

증상: FLOOR MAP 아래에 `positions are approximate - calibration frame
1050x1400 != live 2592x1520`, SETTINGS ▸ Floor calibration 상태 줄에
`live-usable 0/4`. 가구·가시영역(정적 기하)은 그려진다 — 그건 방 cm 좌표라
해상도와 무관하기 때문이고, **못 쓰는 건 실시간 사람 위치**다.

> ⚠ `draw even if the coordinate frame mismatches` 체크는 **문제를 고치는
> 스위치가 아니다.** 어긋난 좌표계로 억지로 찍어 보는 진단용이고, 기본이
> 켜져 있어 "그려지니까 맞겠지"로 오해하기 쉽다.

## 1. 준비

- 카메라 화면이 **평소 운영 상태**여야 한다 — 줌·틸트를 바꾸면 H 가 무효가
  된다. 재캘리브레이션 뒤에는 CAMERA ▸ Image 의 줌을 만지지 말 것.
- 바닥에 **길이를 아는 직선 기준** 두 방향(X·Y)이 보여야 한다 (타일 줄눈,
  벽 모서리, 줄자). 방 전체 크기(가로·세로 cm)도 실측해 둔다.
- VMS 계정은 **관리자** — 전역 적용(모든 VMS)은 관리자만 된다.

---

## 2. 캘리브레이션 웹 UI 열기

VMS ▸ **SETTINGS ▸ Floor calibration ▸ `open web UI`** 링크가 정확한 주소를
연다. 직접 열려면:

```
https://<카메라주소>/home/setup/opensdk/html/test_calibration/index.html?AppName=test_calibration
```

카메라 계정으로 로그인한다. 이 UI 는 **카메라 위에서 도는 앱**
(`test_calibration`)이라, 앱이 Stop 되어 있으면 열리지 않는다
(CAMERA ▸ System ▸ Applications 에서 Running 확인).

---

## 3. 소스 캡처 — **폰 사진을 쓰지 않는다**

`분할` 탭에서:

1. `채널 CH` 에 1~4 를 넣고 **📷 카메라 캡처 (live)** — 또는 `채널 목록`
   `1,2,3,4` 로 **📷 전 채널 캡처**(순서대로 돈다).
2. 캡처가 끝나면 UI 가 `✅ CH1 2592x1520 · NNN KB` 처럼 **해상도를 찍어
   준다. 이 숫자가 2592x1520 인지 반드시 눈으로 확인한다** — 이 절차 전체의
   유일한 성패 조건이다.
3. 같은 화면의 안내대로 **채널마다 `분할 실행`** 을 눌러 바닥선(`/lines`)을
   채운다. 채널 하나씩이다.

> ⚠ **캡처와 분할은 겹쳐 돌리지 않는다** — 추론 중 메모리가 급증해 앱이
> 강제 종료될 수 있다(UI 주석의 경고, RAM 95% 한계).
>
> ⚠ 영상 안에 카메라가 구운 OSD 글자(`CAMERA N`)와 UI 의 CH 번호가 맞는지
> 확인한다. 어긋나면 **뒤 단계가 전부 다른 카메라에 붙는다.**

참고로 SUNAPI 스냅샷도 같은 픽셀 공간을 준다(2026-08-22 4채널 실측 —
전부 2592×1520):

```
GET https://<카메라>/stw-cgi/video.cgi?msubmenu=snapshot&action=view&Channel=<0..3>
```
⚠ 이 경로의 `Channel` 은 **0-based**다(카메라 축). 웹 UI 의 CH 표기는 1-based.

## 4. H 계산 (채널마다)

`캘리브레이션` 탭에서:

1. **📷 카메라에서 불러오기** — 방금 캡처한 그 채널의 소스를 캔버스로 가져온다.
2. 방 크기(가로·세로 cm)를 실측값으로 맞춘다.
3. 화면의 바닥선을 클릭해 **X 에 2개, Y 에 2개**(서로 다른 값) 배정한다.
4. **H 계산**.
5. **검증은 숫자가 아니라 격자로 한다** — 영상에 되쏜 1 m 격자가 바닥을 따라
   반듯하면 맞은 것이다. 휘거나 기울면 3번 배정을 다시 한다.
6. 네 채널 모두 반복한다. (장애물·가구를 쓰려면 그 채널에서 함께 지정한다.)

## 5. 내보내기

**💾 calibration.json 내보내기** — H 가 나온 채널이 전부 담긴다.

내보낸 파일에서 다음을 확인한다(텍스트 편집기로 충분):

```jsonc
{
  "room":     { "width_cm": 1300, "height_cm": 700 },   // 실측값인가
  "channels": {
    "1": { "frame_w": 2592, "frame_h": 1520, "H": [ ... 9개 ... ] },
    "2": { ... }, "3": { ... }, "4": { ... }
  },
  "obstacles": [ { "channel": 1, "name": "table", "footprint": [...] } ]
}
```

- `frame_w/frame_h` 가 **2592 × 1520** 인가 (아니면 3번으로 되돌아간다)
- 채널이 **4개** 다 있는가
- ⚠ **키는 1-based 다** (`"1"` = CH1 = cam1). VMS 는 이걸 입구에서 0-based 로
  바꿔 담는다 — `CalibrationStore::load_json` 한 곳에서만 변환한다.
  손으로 키를 고쳐 0-based 로 만들지 말 것(그러면 VMS 가 0-based 파일로 보고
  변환을 건너뛰어 결과가 같아지지만, 규약이 두 벌이 되어 다음 사람이 틀린다).

## 6. VMS 에 적용

**SETTINGS ▸ Floor calibration**

1. `Load file...` — 파일을 고른다. 이 단계는 **적용이 아니다**(파싱·검증만).
2. `Apply` — 이때 실제로 적용된다.
   - **관리자**: 서버로 발행(retained) → **모든 VMS** 가 받는다.
   - 운영자: 이 계정에만 남는 로컬 오버라이드(서버 무접촉).
3. 상태 줄을 읽는다:

```
active: site_config - live-usable 4/4 - geometry 4/4 - obstacles N
```

**`live-usable` 이 0 이 아니면 성공이다.** FLOOR MAP 아래의
`positions are approximate ...` 문구도 사라진다.

> ⚠ 서버 전역 설정은 **16KB 상한**이다(`cmd/set_site_config`, `too_large`).
> 4채널 + 장애물이면 보통 2~4KB 라 문제없지만, 소스 이미지를 통째로 넣는
> 식으로 파일이 커지면 거절된다.

---

## 7. 검증 — 화면에서 확인할 것 세 가지

1. **SETTINGS 상태 줄**: `live-usable N/4` 가 0 이 아니다.
2. **LIVE ▸ FLOOR MAP**: 사람이 서 있는 자리에 점이 찍히고, 그 점이 방
   도면에서 실제 위치와 맞는다. `positions are approximate` 없음.
3. **CROWD 평면도**: 가시영역·가구가 채널별로 제자리에 있다.

채널이 통째로 밀려 보이면 **채널 매핑**을 의심한다(3번의 OSD 확인, 5번의
키 규약). 한 채널만 뒤틀려 보이면 그 채널의 X·Y 기준선 배정을 다시 한다.

---

## 8. 언제 다시 해야 하나

- 카메라 **줌·틸트·설치 위치**를 바꿨을 때 (H 가 그대로 무효)
- 카메라를 교체하거나 펌웨어로 **해상도 구성**이 바뀌었을 때
- 방 배치가 크게 바뀌어 가구·가시영역이 안 맞을 때
- LIVE 타일 배치(드래그 앤 드롭)는 **관계없다** — 자리만 바뀔 뿐 채널↔H 는
  그대로다 (`WallOrder` 는 표시 순서일 뿐이다).
