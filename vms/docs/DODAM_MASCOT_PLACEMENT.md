## 0. 30초 요약

마스코트를 **다섯 자리**에 넣고, **네 자리에는 절대 넣지 않는다.**

넣는 곳은 전부 *기다리는 화면·비어 있는 화면*이다. 안 넣는 곳은 전부 *사고가
났거나 조작 실수의 대가가 큰 화면*이다. 이 문서의 절반은 후자를 위해 있다 —
귀여운 그림과 "지금 사람이 위험하다"가 같은 화면에 있으면 안 된다.

리소스는 **PNG 한 장만** 리포에 넣고 표시 크기는 런타임에 줄인다.

## 1. 자산

| 항목 | 값 |
|---|---|
| 원본 | `fp_shared_folder/dodam_mascot.png` |
| 크기 | 896 × 1195 px (세로, 비율 0.7498 ≈ **3:4**) |
| 형식 | PNG · 32bpp ARGB — ⚠ **투명 배경이 아니다** (아래) |
| 용량 | 1.63 MB (1,697,391 B) |
| 그림 | 전술 조끼 + 선글라스를 낀 코기, `guardX / INTELLIGENT FIRE & SECURITY` 방패를 든 자세 |
| 마스터 | `fp_shared_folder/dodam_mascot_alpha.png` — 알파 컷본, 캔버스 그대로 896×1195 · 1.21 MB |
| 리포 자산 | `vms/assets/dodam_mascot.png` — 576 × 768 · 8bit 팔레트+tRNS · 96,611 B |
| 재가공 | `fp_shared_folder/make_mascot_asset.py` — 컷 → 중앙 정렬 → 축소를 한 번에 |

⚠ **원본은 투명하지 않다 (08-13 실측).** 배경처럼 보이는 회색 격자는 투명이
아니라 **그려져 있는 그림**이다 — 18.67px 체커가 `#DFDFDF`/`#FAFAFA` 두 레벨로
칠해져 있고 알파는 1,070,720 픽셀 **전부 255**다. 그대로 넣었으면 다크 화면에
밝은 회색 사각형이 떴다. 그래서 리포 자산은 알파 컷을 거친 것이고, 원본을
직접 로드하는 코드는 어디에도 두지 않는다.

컷은 **밝은 무채색을 테두리에서 flood fill** 하는 방식이다. 피사체가 어두운
잉크 외곽선으로 닫혀 있어서 체커와 그 안쪽 흰 키라인이 함께 떨어지고 잉크선에서
멈춘다 — 색만 보고 지우는 것이 아니라 **이어져 있는 것만** 지우므로 흰 털·방패
하이라이트처럼 안쪽에 갇힌 밝은 면은 남는다. 다시 만들 일이 생기면 손으로 하지
말고 `make_mascot_asset.py` 를 돌린다.

**그림 자체가 이미 브랜드를 말한다.** 방패에 로고와 태그라인이 박혀 있다 —
이건 배치에 제약이 된다(§3의 ⚠ 참조). 로고 워드마크 옆에 두면 같은 말이 한
화면에서 두 번 나온다.

## 2. 이 마스코트가 하는 일 / 안 하는 일

**하는 일** — 비어 있는 자리를 채우고, 기다리는 시간을 덜 삭막하게 만든다.
관제 화면은 하루 종일 켜져 있고 대부분의 시간은 아무 일도 안 일어난다.
"아무 일 없음"이 고장처럼 보이지 않게 하는 것이 이 그림의 역할이다.

⚠ **안 하는 일 — 상태를 표시하지 않는다.** 마스코트의 표정·자세로 정상/경보를
구분하는 변형(웃는 도담 / 놀란 도담)은 만들지 않는다. 상태는 색·아이콘·문구가
이미 말하고 있고, 거기에 그림을 하나 더 얹으면 **읽는 사람이 어느 쪽을 믿어야
하는지** 정해줘야 한다. 한 화면에서 같은 사실을 두 곳이 말하면 언젠가 갈린다
(경보 팝업이 고정 오프셋으로 겹쳤던 일과 같은 종류의 실수다).

## 3. 넣는 자리 (5곳)

| # | 자리 | 표시 폭 | 불투명도 | 우선 |
|---|---|---|---|---|
| 1 | **로그인 화면** — 카드 **바깥** 왼쪽 | 220 px | 1.0 | P1 |
| 2 | **기동 대기(스플래시)** — 세션 확인 중 | 160 px | 1.0 | P1 |
| 3 | **TRACKING 빈 상태** — `no target` 자리 | 96 px | 0.25 | P2 |
| 4 | **경보 피드 빈 목록** — 미확인 경보 0건 | 96 px | 0.25 | P2 |
| 5 | **REPORT 헤더** — 문서 표지 느낌 | 64 px | 0.9 | P3 |

**① 로그인 화면 (P1).** 이 앱에서 유일하게 아무 일도 일어나지 않는 화면이고,
가로로 넓게 비어 있다(카드는 1600px 화면 한가운데 400px 남짓).
⚠ **카드 안에 넣지 않는다.** 카드 상단에 `GUARDX VMS 1.0` 워드마크가 있어서,
방패의 `guardX` 로고와 12px 거리에서 두 번 나온다. 카드 왼쪽 바깥 여백에
세워 두면 겹치지 않고 화면의 빈 쪽도 채운다.

**② 기동 대기 (P1).** 저장된 세션으로 자동 로그인하는 동안(§4a) 최대 6초
빈 화면이다. 지금은 카드가 숨겨진 채 아무것도 없다.

**③④ 빈 상태 (P2).** `no target` · `no detections` · 경보 0건은 **정상**인데
화면상으로는 고장과 구분이 안 된다. 흐린 마스코트 + 기존 문구면 "여기는
비어 있는 게 맞다"가 읽힌다. ⚠ 불투명도 0.25 를 넘기지 않는다 — 이 자리는
언제든 실제 대상/경보로 바뀌고, 그때 마스코트가 그 위에 남아 있으면 안 된다
(값이 들어오면 **위젯을 교체**한다. 겹쳐 그리지 않는다).

**⑤ REPORT 헤더 (P3).** 인쇄·공유되는 화면이라 브랜드가 한 번 더 나올 자리로
자연스럽다. 작게, 문서 표지의 도장처럼.

## 4. ⚠ 절대 넣지 않는 자리 (4곳)

| 금지 자리 | 이유 |
|---|---|
| **경보 팝업 4종** (혼잡·화재·음향·장비) | 사람이 위험하다는 화면이다. 이 팝업의 `확인`은 미확인 경보를 지우는 조작이고, 그 옆에 마스코트가 있으면 누르는 손이 가벼워진다 |
| **영상 타일 위** | 감시 대상 위에 그림을 얹지 않는다. 박스·블러와 겹치면 판단을 가린다 — 화면이 곧 증거다 |
| **화재 임계 · 액추에이터 조작** (SETTINGS 화재 폼 · DEVICE) | 실수의 대가가 가장 큰 두 화면이다. 여기는 밀도가 높고 시선이 값에 붙어 있어야 한다 |
| **로딩 표시 대체** | 움직이는 마스코트는 만들지 않는다. LIVE 는 프레임 예산이 빠듯하고, 애니메이션은 "멈춘 화면"과 "도는 화면"의 구분을 흐린다 |

상단바도 넣지 않는다 — 거기는 CAM·RPI·DB·CPU 가 사는 **상태 줄**이고,
정보가 아닌 것이 끼면 그 줄의 규칙이 깨진다.

## 5. 표시 규격

- **비율 3:4 고정.** 리포 자산은 576×768 로 **정확히 3:4** 다. 원본 캔버스는
  0.7498 인 데다 여백이 한쪽으로 치우쳐 있어서(좌 99 · 우 33 · 상 68 · 하 46 px)
  그대로 줄이면 도담이 오른쪽으로 밀린다 — 내용 bbox(764×1081)만 떼어
  3:4 캔버스(811×1081) 한가운데 다시 놓고 줄였다. 코드에서는 폭만 정하고
  높이는 `w * 4 / 3` 으로 계산한다 — 두 값을 손으로 적으면 언젠가 어긋난다.
- **여백**: 마스코트 폭의 25% 이상. 글자와는 12px 이상. 자산 안쪽에도 좌우
  23px(원본 기준)씩 투명 여백이 있으므로, 표시 폭 220px 이면 실제 그림은
  약 207px 다. 여백을 셀 때 이걸 빼고 세지 않는다.
- **그림자·테두리·배경 원형 금지.** ⚠ 투명 배경을 **가진 것은 리포 자산과
  마스터뿐이다.** 화면 코드는 `:/img/dodam_mascot.png`(= `Theme::mascot()`)만
  쓴다 — 공유폴더 원본을 직접 로드하면 체커 무늬가 딸려 온다(§1). 흰 키라인도
  컷에서 함께 떨어졌으니 테두리를 다시 그려 넣지 않는다.
- **다크/라이트**: 그림은 그대로 둔다. ⚠ 라이트 테마의 흰 면 위에서는 방패의
  어두운 금속이 무겁게 떨어진다 → 라이트에서만 불투명도 0.85 (다크 1.0).
  색을 바꾸거나 반전시키지 않는다. 코드에서는 `Theme::mascot_opacity()` 가
  이 값을 돌려주므로, 자리별 불투명도(빈 상태 0.25 등)에 **곱해서** 쓴다:
  `p.setOpacity(0.25 * Theme::mascot_opacity())`.
- **잘라내기 금지.** 방패나 발이 잘리면 다른 그림이 된다. 자리에 안 들어가면
  **줄이고, 그래도 안 되면 안 넣는다.** (위의 중앙 정렬은 **빈 여백**만 고른
  것이라 여기 해당하지 않는다 — 피사체는 한 픽셀도 자르지 않았다.)

## 6. 리소스 처리

**리포에는 한 장만 넣는다** — `vms/assets/dodam_mascot.png`, **폭 576px 로 축소**한 것.

- 576px = 최대 표시 폭(220) × 2(HiDPI) 를 넘기는 첫 크기다. 그보다 큰 원본을
  실행 파일에 넣을 이유가 없다.
- ⚠ 원본 1.63 MB 를 그대로 넣지 않는다. 리소스는 **실행 파일에 통째로 들어간다**.
  `pngquant`(8bit + alpha)를 거치면 200KB 안쪽이 되고 이 그림에서는 차이가 안 보인다.
- 원본(896px)은 공유폴더에 그대로 둔다 — 재가공의 출처다.

CMake 등록은 폰트와 같은 모양으로 한다. ⚠ **`BASE` 를 빼면 안 된다** —
빼면 별칭이 `:/img/assets/…` 가 되고 코드가 못 찾는다(폰트에서 실제로 겪은 함정,
`CMakeLists.txt` 120줄 주석 참조):

```cmake
qt_add_resources(gstream_VMS "vms_img"
    PREFIX "/img"
    BASE "assets"
    FILES assets/dodam_mascot.png
)
```

**로드는 한 곳에서만.** `Theme` 에 접근자 하나를 두고 `QPixmapCache` 로 캐시한다:

```cpp
/// @brief 마스코트 픽스맵 (폭 px, 높이는 3:4 로 계산). 캐시된다.
static QPixmap Theme::mascot(int width_px);
```

다섯 자리가 각자 `QPixmap(":/img/dodam_mascot.png").scaled(...)` 를 부르면
같은 축소를 다섯 번 하고, 테마 전환마다 또 한다.

## 8. 정해야 할 것

1. **이름 표기** — UI 문구는 전부 영어라 화면에는 `DODAM` 으로 적는다.
   문서·주석은 한국어(도담). 이 문서는 그 규칙을 따랐다.
2. **로그인 화면 배치** — 카드 왼쪽 바깥이 맞는지는 **픽셀로 확인해야 한다.**
   창 폭이 1536(125% 노트북)까지 줄어드는데, 그때 마스코트가 카드를 밀거나
   화면 밖으로 나가면 **넣지 않는 쪽**이 맞다(창 최소 크기를 마스코트가
   볼모로 잡는 것이 4번 신고의 구조적 원인이었다).
3. **리포에 이미지 커밋** — 지금까지 리포에 이미지 자산이 없다(폰트·셰이더뿐).
   200KB 한 장을 넣는 것에 합의가 필요하다.
4. **P3(REPORT)** 는 인쇄물에 들어가므로 대외 문서에 마스코트를 쓸지와 함께
   판단한다.
