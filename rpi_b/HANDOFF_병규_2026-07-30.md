## 1. `task_vms` dates 쿼리 최적화

### 현상 (실측)

`publishVmsState()`의 날짜 목록 조회가 **detections 전 행을 스캔**한다.

```sql
SELECT DISTINCT (ts AT TIME ZONE $1::text)::date AS day FROM detections
```

- 실측 2026-07-29: **134만 행 / 0.88초**
- 보존 14일이 다 차면 **~2초 이상**으로 늘어난다 (행 수에 선형)

### 왜 문제인가

폴러는 **단일 스레드 1초 틱 루프**다. 이 쿼리는 `cfg_interval_s`(기본 30초)
틱에서 도는데, 도는 동안 루프 전체가 멈춘다 — 2초 걸리면 `det_interval_s`
(2초) 주기의 detections 적재가 그만큼 밀린다. 즉 **화면에 보이는 감지가
늦어지는 원인**이 된다.

### 개선안

날짜 목록은 **일 파티션 이름이 이미 들고 있다.** 행을 볼 필요가 없다.

```sql
SELECT to_date(substring(relname from '\d{8}$'), 'YYYYMMDD') AS day
  FROM pg_class
 WHERE relname ~ '^detections_p\d{8}$'
 ORDER BY day
```

카탈로그 조회라 **~1ms, 행 스캔 0**이다.

### 고칠 위치

`rpi_b/src/MqttDb/task_vms.cpp` → `publishVmsState()` 안의 `dates` 발행 블록
(주석 `// ── dates: CROWD 화면 우측 날짜 목록 ──`). 발행 형식은 그대로 두고
안쪽 SELECT만 교체하면 된다. 결과 payload 계약은 바뀌지 않는다:

```json
{"node_id":"rpib","timestamp":<ms>,"dates":["2026-07-29","2026-07-30"]}
```

### 주의

- **타임존**: 기존 쿼리는 `AT TIME ZONE 'Asia/Seoul'`로 KST 기준 날짜를 냈다.
  파티션 이름이 어느 기준으로 잘렸는지 확인할 것 — 파티션이 UTC 경계로
  만들어졌다면 자정 근처 하루가 어긋날 수 있다. 어긋나면 **VMS 히트맵에서
  그 날짜가 빈 채로 나온다**(조회 자체는 성공하므로 조용히 틀린다).
  확인: `SELECT relname FROM pg_class WHERE relname ~ '^detections_p\d{8}$'`
  결과와 기존 쿼리 결과를 하루치 대조.
- 파티션이 drop되면 목록에서도 빠지는데, 이건 **기존 동작과 동일**하다
  (`rpi_b/Database/schema.sql`의 보존 정책).
- 빈 파티션(행 0)도 목록에 뜬다. 기존엔 안 떴다 — VMS는 그 날짜를 고르면
  빈 히트맵을 그리므로 기능상 무해하지만, 신경 쓰이면 `WHERE`에
  `AND pg_relation_size(oid) > 0` 정도로 거를 수 있다.

### 검증

```bash
# 1) 개선 전후 시간 비교 (실기기 psql)
\timing on
SELECT DISTINCT (ts AT TIME ZONE 'Asia/Seoul')::date FROM detections;
SELECT to_date(substring(relname from '\d{8}$'), 'YYYYMMDD') FROM pg_class WHERE relname ~ '^detections_p\d{8}$';

# 2) 발행 payload 확인 (VMS가 실제로 쓰는 것)
mosquitto_sub -h localhost -t 'guardx/db/rpib/dates' -v -C 1
```

VMS의 CROWD 화면 우측 날짜 목록이 이전과 같으면 성공이다.

## 2. 채널 이름을 DB에서 읽어 표시

### 현상

채널 이름이 **세 군데에 따로** 있고, 어느 것도 DB를 보지 않는다.

| 어디 | 지금 | 문제 |
|---|---|---|
| 카메라 영상에 번인된 OSD | `CAMERA 1` + 날짜/시각 | 영상 픽셀에 새겨져 지울 수 없다. VMS 타일 좌상단 채널명과 **겹쳐서 읽기 어렵다** |
| VMS 타일·리포트 | `Theme::channel_name()` 하드코딩 `{"CH1 · LOBBY EAST", …}` | 운영자가 구역 이름을 바꿔도 VMS는 옛 이름을 계속 보여준다 |
| DB | `zones.zone_name` | **여기가 진실원천이어야 하는데 아무도 안 읽는다** |

### 목표

`zones.zone_name`을 단일 진실원천으로 만들고, 카메라 번인 OSD는 끈다.

### 3단계

**① 카메라 OSD 끄기** — 카메라 웹 뷰어(또는 SUNAPI)에서 좌측 상단 텍스트 +
카메라 번호 표기를 끈다. 4채널 전부.
*주의*: 날짜/시각 OSD까지 끌지는 팀 결정 필요 — 녹화본 증빙에 쓰인다면 남길
것. 이름만 끄는 것으로 충분하다.

**② 폴러가 이름을 실어 보낸다** — `rpi_b/src/MqttDb/task_vms.cpp`의
`queryZones()`에 `zone_name`을 한 줄 추가한다. 지금 payload에는 없다:

```cpp
"      'zone_id', z.zone_id, 'channel', z.channel,"
"      'zone_name', z.zone_name,"          // ← 추가
"      'capacity_limit', t.capacity_limit,"
```

계약이 넓어지기만 하므로 **기존 VMS와 호환된다** (모르는 필드는 무시).

**③ VMS가 그 이름을 쓴다**

- `vms/zone_config.{h,cpp}` — `capacity()`·`warn_ratio()` 옆에
  `QString name(int channel)` 추가. 캐시 구조는 그대로.
- `vms/theme.cpp` `channel_name()` — `ZoneConfig::name(ch)`가 비어 있지
  않으면 그걸 쓰고, 아니면 지금 하드코딩 값으로 폴백.
  **폴백을 없애지 말 것**: 브로커가 죽어도 타일에 이름은 떠야 한다(fail-soft).
- 표시 형식은 `CH1 · LOBBY EAST`처럼 "CH번호 · 이름"을 유지한다. VMS 여러
  곳이 `" · "`로 잘라 쓰고 있다 (`alert_popup.cpp`, `report_page.cpp`의
  `split_channel_name`) — 형식을 바꾸면 그쪽도 함께 고쳐야 한다.

### 검증

```bash
# DB에서 이름을 바꾸고
sudo -u postgres psql -d guardx -c "UPDATE zones SET zone_name='LOBBY WEST' WHERE zone_id=2;"
# 폴러가 재발행하는지 (설정 틱 30초 이내)
mosquitto_sub -h localhost -t 'guardx/db/rpib/zones' -v -C 1
```

VMS를 **재시작하지 않고** 타일 이름이 바뀌면 성공이다 (retained + 구독 구조).

## 3. `FloorCanvas`를 `crowd_page.cpp`에서 분리 (07-31 추가)

### 현상

`vms/crowd_page.cpp` 한 파일에 두 클래스가 산다:

- `FloorCanvas` — 평면도 렌더러. 카메라 좌표 → 평면도 투영(`to_floor`),
  채널별 방위·화각 표(`FANS[4]`), 히트맵 셀 그리기
- `CrowdPage` — 데이터·UI. 날짜 캐시, MQTT heatday 요청, 슬라이더

### 왜 분리하나

TRACK 화면(네 담당)이 궤적을 평면도 위에 그리려면 `FloorCanvas`가 필요하다.
지금은 `crowd_page.h`를 include해야 쓸 수 있는데, 그러면 CrowdPage의 데이터
로직까지 딸려온다.

### 작업

1. `FloorCanvas`(+ `FANS`, `to_floor`, `FLOOR_W/H` 상수)를
   `floor_canvas.{h,cpp}` 새 파일로 이동 — **로직 변경 없이 이동만**
2. `crowd_page.{h,cpp}`는 include 교체
3. `vms/CMakeLists.txt` 소스 목록에 두 파일 추가
4. TRACK에서 선을 그리려면 `set_cells()` 옆에 `set_path()` 추가 정도면 된다
   (원 제안: `VMS_CODE_MAP.md` §4-4)

### 검증

CROWD 화면 히트맵이 이전과 동일하게 그려지면 끝. 헤더를 옮겼으므로
**클린 빌드**(`--clean-first`) 필수 — 증분 빌드가 헤더 의존을 놓치면
힙 깨짐(`VMS_CODE_MAP.md` §6 실사고).
