· 카메라 앱 `test_calibration` v3.4

**목적**: CCTV 화면의 사람 발밑 좌표를 **하나의 방 평면도 위 cm 좌표**로 찍는다.

다른 답을 낼 여지를 없애기 위해서다.

## 1. `.cap` 빌드와 설치

### 1.1 빌드

Docker(OpenSDK 툴체인) 안에서 돈다. VM의 공유폴더 기준:

```bash
bash /mnt/c/veda_project/vm_shared/build_cap.sh test_calibration
```

결과: `vm_shared/test_calibration.cap`

### 1.2 버전 올리기 — 잊으면 설치가 조용히 무시된다

`config/app_manifest.json` 의 `AppVersion` 을 **매번 올려야** 한다.
같은 버전이면 카메라가 재설치를 건너뛰고, 코드를 고쳤는데 화면이 그대로라
디버깅에 시간을 버리게 된다.

```json
{ "AppName": "test_calibration", "AppVersion": "3.4", "Permission": [] }
```

### 1.3 설치

카메라 웹 설정 → **Open Platform** → 앱 업로드 → `.cap` 선택 → 실행.

### 1.4 ★ 매니페스트 3파일 동기화 (반복해서 당한 함정)

컴포넌트를 추가·개명하면 **세 파일이 서로를 가리켜야** 한다. 하나라도
어긋나면 앱이 조용히 안 뜨고 HTTP 502만 돌아온다 — 에러 메시지가 없어서
원인을 찾기 어렵다.

| 파일 | 무엇을 적나 |
|---|---|
| `app/src/floor_seg/manifests/FloorSeg_manifest_instance_0.json` | 이 컴포넌트가 **누구에게 보내나** (`ReceiverNames`) |
| `app/src/PLifeCycleManagermanifest.json` | 컨테이너가 **어떤 컴포넌트를 적재하나** |
| `app/res/models/AppDispatcher_manifest_instance_0.json` | 디스패처가 **누구에게 HTTP를 넘기나** |

세 번째 파일만 `src/*/manifests/` 에 원본이 없다 — `res/models/` 의 것이
그 자체로 원본이다. 다른 두 개처럼 빌드 시 복사되지 않으니 직접 고쳐야 한다.

`FloorSeg` 의 `ReceiverNames` 에 **`"OpenPlatform"` 이 반드시 있어야** 한다.
실시간 스냅샷(`eAppSnapshotJpeg`) 응답이 이 경로로 돌아오기 때문이다.

### 1.5 카메라 쪽 HTTP 엔드포인트

| 경로 | 하는 일 |
|---|---|
| `/health` | 살아 있나 |
| `/capture?channel=N` | 채널 N 실시간 프레임 1장 (JPEG) |
| `/images` | `res/models/` 의 정적 사진 목록 |
| `/segment` | 분할 + 선 검출 실행 |
| `/lines` | 검출 결과(선·접지점) JSON |
| `/result` | 분할 시각화 이미지 |

## 2. 웹 UI — 캘리브레이션

주소:

```
https://<카메라IP>/home/setup/opensdk/html/test_calibration/index.html?AppName=test_calibration
```

VMS **SETTINGS → 캘리브레이션 카드**의 링크가 이 주소를 만들어 준다
(`Credentials::calibration_ui_url()`).

### 2.1 방 크기 입력 — 가장 먼저

상단 `방 가로` / `세로` (cm). **이 값이 모든 것의 기준**이다:

- 역할 버튼 라벨 (`우측(X=1300)`, `하단(Y=700)`)
- 내보낸 `room.width_cm/height_cm`
- VMS 지도의 종횡비·1m 격자·모든 좌표 정규화

나중에 바꾸면 이미 지정한 값이 자동으로 따라 바뀐다(`calResync`).

### 2.2 ① 분할 탭 — LIVE 캡처

드롭다운에서 **LIVE1~LIVE4** 를 고르고 `분할 실행`.

> ★ **반드시 LIVE 를 써야 한다.** `cam1`·`cam2` 같은 정적 사진으로 만든 H 는
> VMS 에서 실시간 좌표 변환에 **쓸 수 없다**. 폰 사진은 CCTV 와 위치·각도·
> 렌즈가 달라서 H 자체가 다른 변환이고, 해상도 스케일로 고칠 수 없다.
> 정적 사진은 UI 연습·모양 확인용이다.

응답의 `w`/`h` 가 **2592×1520** 인지 확인한다. VMS 의
`FloorCanvas::FRAME_W/FRAME_H` 와 같아야 `usable` 이 켜진다.

```json
{ "ok": true, "src": "live:1", "w": 2592, "h": 1520,
  "work_w": 1400, "work_h": 821 }
```

`work_w/h` 는 내부 처리용 축소 크기다(메모리 보호). 검출된 선 좌표는
원본 해상도로 되돌려서 준다 — H 가 2592×1520 기준이 되도록.

### 2.3 ② 캘리브레이션 탭 — 역할 지정 (사람이 필요한 유일한 단계)

검출된 선 목록에서 **각 선이 방의 어디인지** 눌러 준다.

| 버튼 | 뜻 |
|---|---|
| `좌측(X=0)` `우측(X=1300)` | 세로 경계 — X 좌표를 고정 |
| `상단(Y=0)` `하단(Y=700)` | 가로 경계 — Y 좌표를 고정 |
| `X좌표` `Y좌표` | 그 외 위치 — cm 를 직접 입력 |

**최소 조건: 서로 다른 값이 X 2개 · Y 2개.** 호모그래피 8자유도를 채우려면
독립 제약 4개가 필요해서다.

`H 계산` 을 누르면 영상에 **1m 격자가 되쏘아진다.**

> ★ **검증은 숫자가 아니라 격자로 한다.** RMS 같은 수치는 "내가 찍은 점에
> 얼마나 잘 맞나"일 뿐이라, 점을 잘못 찍으면 오차가 작게 나오면서 틀린다.
> 되쏜 격자가 **바닥 무늬·가구 접지선과 나란한가**를 눈으로 본다.
> H 계산에 **안 쓴 선**이 제자리에 오는지 보면 더 확실하다.

### 2.4 ③ 전체 지도 탭 — 4채널 합쳐 보기

채널별 가시영역이 색으로 겹쳐 그려진다. 여기서 볼 것:

- 채널 간 **가구 위치가 어긋나지 않는가** — 어긋나면 그만큼이 정합 오차다
- 방 밖으로 삐져나오지 않는가
- 사각지대가 어디인가

### 2.5 ④ 내보내기 → `calibration.json`

```json
{
  "room": { "width_cm": 1300, "height_cm": 700 },
  "channels": {
    "1": {
      "H": [ … 9개, 행 우선 3x3 … ],
      "frame_w": 2592, "frame_h": 1520,
      "source": "live:0",
      "made_at": "2026-08-11T…",
      "coverage_poly": [[399,0],[549,317],[347,520],[0,277],[0,0]]
    }
  },
  "obstacles": [
    { "channel": 1, "name": "cabinet", "footprint": [[160,0],[403,0],[403,46],[160,46]] }
  ]
}
```

| 필드 | 왜 있나 |
|---|---|
| `H` | 채널 픽셀 → 방 cm. 실시간 발밑점 변환에 쓴다 |
| `frame_w/h` | **이 H 를 만든 좌표계.** 받는 쪽이 이걸로 거른다 |
| `coverage_poly` | 가시영역 **꼭짓점**(방 cm). 격자가 아니라 다각형이라 경계가 정확하다 |
| `obstacles[].footprint` | 가구 4점(방 cm) |

> `coverage_poly` 는 영상 사각형을 ①지평선 너머 ②방 경계로 두 번 잘라
> (Sutherland–Hodgman) 얻은 다각형이다. 투영은 직선을 직선으로 보내므로
> 가시영역 경계는 원래 직선이다 — 예전처럼 20cm 격자로 근사하면 계단으로
> 보인다.

## 3. VMS (Qt) — 불러오기와 표시

### 3.1 불러오기

**SETTINGS → 캘리브레이션 카드 → `📂 calibration.json 불러오기`**

`CalibrationStore` 가 파일을 읽어 `changed()` 를 쏘고, CROWD·FLOOR MAP 이
그 신호로 다시 그린다.

### 3.2 신뢰 판정 — `usable` 과 `geo_usable` 은 다르다

| 플래그 | 조건 | 무엇에 쓰나 |
|---|---|---|
| `usable` | H 있음 **AND** `frame_w/h == 2592×1520` | **실시간 발밑점 변환**(`to_floor`) |
| `geo_usable` | H 있음 | **가시영역·가구**(정적 기하) |

둘을 나눈 이유: 가시영역과 가구는 웹 UI가 "그 사진 좌표계"에서 이미 cm 로
계산해 보낸 **정적** 결과라 라이브 프레임 해상도와 무관하다. 하나로 묶으면
사진 기준 채널의 (정확한) 가시영역까지 안 그려진다.

반대로 실시간 점 변환은 라이브 스트림 좌표를 H 에 그대로 넣으므로 해상도가
반드시 같아야 한다. **여기서 조용히 틀린 좌표를 쓰느니 안 그리는 게 낫다** —
`to_floor()` 는 못 믿는 채널에 "모른다" 좌표를 주고 호출부가 건너뛴다.

### 3.3 CROWD 페이지

- **히트맵** — DB 집계를 `to_floor()` 로 방 좌표에 찍는다 (`usable` 필요)
- **화각** — `coverage_poly` 를 채널 색으로 (상단 CH1~4 토글)
- **가구** — 중립색(회청) 고정. 채널 색과 겹치지 않게 (CH3 이 호박색이라)
- **1m 격자 · 방 외곽** — 방 크기 기준

채널 색: CH1 파랑 `#5b8dd9` · CH2 초록 `#3fd07a` · CH3 호박 `#d9a13f` ·
CH4 연빨강 `#d95f5f` (웹 UI `CH_COL` 과 동일)

### 3.4 FLOOR MAP (TRACKING 패널)

캘리브레이션이 있으면 **한 방 실측 도면**, 없으면 예전 2×2 개략도.

실측 모드에서는 네 채널을 한 방에 겹쳐 그리므로 대상이 CH1→CH2 로 넘어가도
**동선이 끊기지 않는다**(개략도에서는 칸이 바뀌며 끊겨 보였다).
화각은 그리지 않는다 — 동선을 가리기만 하고, 그건 CROWD 가 보여 준다.

### 3.5 종횡비

`FLOOR_W/FLOOR_H`(1000×620)는 **내부 정규화 좌표일 뿐** 방의 비율이 아니다.
`view_transform()` 이 방 크기(1300×700)의 비율로 되살려 그린다. 이걸 안 하면
가로가 13% 눌려서 지도에서 거리를 눈으로 재면 틀린다.

## 4. 각도를 바꿨을 때 — 다시 해야 하는 것

카메라 각도·위치를 바꾸면 **H 가 무효**가 된다. 2장 전체를 다시 밟는다.

```
① 분할 탭 → LIVE 캡처 → 분할 실행
② 캘리브 탭 → 역할 지정 (X 2개 · Y 2개) → H 계산 → 격자로 검증
③ 전체 지도에서 4채널 정합 확인
④ 내보내기 → VMS SETTINGS 에서 불러오기
```

②만 사람 손이 필요하다 — "이 선이 왼쪽 벽이다"는 사람만 아는 정보라
자동화할 수 없다. 나머지는 클릭 몇 번이다.

방 크기가 그대로면 ①에서 채널 하나만 다시 잡아도 된다(다른 채널 H 는 유지).

## 5. 아직 안 된 것

| 항목 | 상태 |
|---|---|
| **라이브 프레임 H 실측 검증** | ❌ 아직 한 번도 안 함. 지금까지 데이터는 전부 사진 기준이라 `usable=false` — 실시간 히트맵·동선이 안 나온다. **이게 다음 할 일** |
| `calibration.json` 자동 전달 | 수동 파일 복사. MQTT 자동 수신은 의도적으로 미룸 |
| 렌즈 왜곡 보정 | 없음. 체스보드 기반 `cv::fisheye::calibrate` 필요 (연구문서 §3.6 격차 1번) |
| 기준점 개수 | 4~5개로 최소치. 벽에서 떨어진 점을 늘리면 RANSAC 이 의미를 갖는다 (격차 2번) |
| 카메라 위치 표시 | H 만으로는 못 구한다(내부 파라미터 필요). 지도에 CCTV 점을 안 찍는 이유 |
| VMS 크래시 (`ChannelSync`) | 미해결. 캘리브레이션과 무관한 것으로 보이나 확인 안 됨 |

## 6. 자주 막히는 곳

| 증상 | 원인 |
|---|---|
| 앱 설치했는데 화면이 그대로 | `AppVersion` 을 안 올림 (§1.2) |
| HTTP 502, 로그도 없음 | 매니페스트 3파일 불일치 (§1.4) |
| `/capture` 응답 없음 | `ReceiverNames` 에 `"OpenPlatform"` 누락 |
| VMS 에 화각이 안 그려짐 | 구버전 `calibration.json` (`coverage_poly` 없음) → 다시 내보내기 |
| 히트맵이 "미보정 채널"만 뜸 | 사진 기준 H (`frame_w/h ≠ 2592×1520`) → LIVE 로 다시 |
| 지도가 웹뷰어와 다른 모양 | 종횡비 (§3.5) — 수정됨 |
| 방 크기를 바꿔도 버튼 숫자가 그대로 | `calResync` 버그 — v3.4 에서 수정됨 |
